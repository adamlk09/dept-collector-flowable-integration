1. The business problem

A customer stops paying a debt. The collection business must answer one question for every file: “what do we do with this debt file today?”

  • Sometimes the answer is gentle: a first reminder, a phone call.
  • Sometimes it is serious: escalate, hand the file to pre-legal, launch legal action.
  • Sometimes there is nothing to do: the debt is already paid (close), or we cannot act yet (missing information), or we cannot even reach the debtor (research first).

workflow-service is the engine that makes this decision and then runs the chosen action as a workflow. The decision is categorical — the file is classified using a handful of business facts. There is no numeric scoring: no “risk score of 73”. The business speaks in situations and treatments, and so does the service.

2. The 7 decision facts

To classify a file, the service looks at seven facts about the debtor and the debt.

FactThe business question it answersPossible values (business meaning)
Client infoIs the debtor's file complete enough to act on? Complete · Incomplete — if incomplete, we cannot legally start collection
Contract statusWhat is the state of the underlying contract? Active · Suspended · Terminated
Debt statusWhat is the state of the debt itself? Open · Partially paid · Paid
Payment historyHow has the debtor been paying? Good · Irregular · No payment at all
Collection stageHow far have collection actions already gone? First contact · One follow-up · Many failed follow-ups
Promise statusDid the debtor promise to pay — and keep the promise? No promise · Promise active · Promise kept · Promise broken
ReachabilityCan we currently reach the debtor? Reachable · Unreachable
Missing facts are handled safely If a fact is not provided, the service assumes the most neutral value (e.g. client info complete, debt open, no promise). The file always gets classified — a caller that only knows the debt and customer still works.

3. The 8 situations & their treatment

The decision has eight possible outcomes. Each one is a real business situation, and each one has its own treatment (a dedicated workflow).

SituationWhen it happens (business meaning)What the service does
FIRST_CONTACTFirst unpaid instalment; nothing has been done yet Send a friendly reminder (SMS/email)
FOLLOW_UPThe debtor was already contacted once, still no payment Schedule a phone call
PROMISE_BROKENThe debtor promised to pay and did not keep the promise Escalate: reinforced / intensive contact
PRE_LEGALMany follow-ups failed without result Hand the file to the pre-legal service
LEGALTerminated contract + no payment + many failed follow-ups Launch legal action
CLIENT_INFORMATION_INCOMPLETEThe file cannot be worked on (missing info) Ask the agent to complete the client information
DEBT_CLOSEDThe debt is already paid Close the file
INFO_RESEARCHThe debtor cannot be reached Run an information-research mission (find new contact details)

4. The decision logic — priority rules

The rules are evaluated in a strict order: the most blocking or escalating situation wins. It is the same priority a collection manager would apply by hand.

  1. Incomplete client info blocks everything else — we cannot act on a file we do not understand.
  2. Debt paid → nothing left to collect → close the file.
  3. Debtor unreachable → first find them (research), then collect.
  4. Legal conditions met (terminated contract + no payment + many follow-ups) → legal action.
  5. Many failed follow-ups → pre-legal transfer.
  6. Broken promise → escalation / intensive contact.
  7. Already contacted once → follow-up phone call.
  8. Otherwise → first contact, friendly reminder (the default for a fresh, ordinary file).
Business continuity is guaranteed If the decision engine is temporarily unavailable, a built-in backup applies the exact same rules and the file still gets classified. The business never sees a blocked file because of a technical failure.

5. The workflow in action

Once the situation is known, the file is routed to its treatment, the treatment is executed, and the outcome is reported.

Step by step, in business words

  1. The file arrives — the caller identifies the debt and the customer.
  2. The file is validated — both must be identifiable, otherwise the treatment cannot start.
  3. The situation is decided — using the priority rules of §4.
  4. The file is routed — each situation goes to its own treatment workflow.
  5. The treatment runs — the action is applied end to end (reminder sent, task created, file handed over, legal launched, file closed, etc.).
  6. The outcome is reported — the caller learns exactly what was decided, why, and what was done.

6. Risk & outcome

Risk level (segment)

Beyond the situation, each file gets a risk level used for prioritisation by the rest of the platform:

RiskSituationsMeaning
HIGH_RISKLEGAL · PRE_LEGAL · PROMISE_BROKEN The file is serious or worsening — priority handling
LOW_RISKEverything else Standard handling

Outcome status

StatusMeaning
COMPLETEDThe treatment finished cleanly (reminder sent, call scheduled, file handed over, action launched)
PENDING_INFOWaiting on human input — the agent must complete client info, or the research mission must return
CLOSEDThe file is closed (debt paid)
The answer the business gets For every file the service returns: the situation decided, the reason (which fact triggered it), the risk level, the action applied and the status of the treatment. No magic — the decision is always explainable.
